# 使用指南

[← 返回 README](../README.md)

## 群聊规则

- 每条消息以 `@收件人` 开头；连续多个句首 @ 是多个收件人。支持中文和英文字母开头的名称，可含数字、`_`、`-`，最多 40 个字符。
- `@claude1，你工作做完了告诉@claude2` 只触发 claude1。
- `@claude1 @codex1 请分别检查` 同时触发两个。
- `@all`、`@everyone`、`@所有人`、`@全体` 发给其他 worker，不包含私有 manager。
- `@admin`、`@管理员` 指向群管理员。管理员也有自己的群聊名称。
- 新 session 先注册待命，只有管理员首次直接 @ 或 @all 才激活。agent 的 @ 不会激活待命成员，也不会回放激活前的任务。
- 引用以消息 ID 关联原消息，展示原发件人、时间和正文。引用中的 @ 不触发任何任务。
- worker 可分页读取全部公共历史，不限于自己收到的消息；manager 私聊只对该 manager 和人类管理员可见。服务端同时过滤历史、引用、成员信息和任务上下文。读历史不会触发工作。
- 每个 session 一次只处理一个任务。不同 session 可以并行；普通消息中的后续点名排队。agent 可主动用 [Steer](#运行中补充steer) 给正在工作的同伴发补充；管理员也可点击消息「排队中」旁的 Steer 按钮，将这条消息注入接收者的当前任务。

## 发送消息

- 输入框上方的 `To` 一行选择实际收件人，默认 @所有人；选择个人会取消所有人，选择所有人会清除个人选择。选择跨消息和刷新保留，正文中的 @ 只作指代。
- 正文输入 `@` 后自动推荐当前角色，继续输入可筛选，上下键选择、Enter / Tab 补全、Esc 关闭；也支持鼠标和触屏选择。已关闭角色仍可作为正文提及，已删除角色不会推荐。
- Enter 发送，Shift+Enter 换行；中文输入法确认候选时不会误发送。输入框随内容增高。
- 点收件人栏右侧的「附件」添加图片或文件。可以和正文一起发送，也可以只发附件。每条最多 5 个，单个最多 10 MiB。附件遵循消息的可见权限，点文件名可以下载。
- 接收任务的 Bridge 会把原文件保存到该 workspace 的 `.agentchat/rooms/<群聊 ID>/uploads/`，再把文件名和本地路径加入提示词。能否读取具体格式由 harness 的工具和权限决定。发送附件前，请将对应的 Bridge 更新到支持附件的版本。
- manager 私聊与公开讨论共用消息流，带「仅你与 manager 可见」标记；点击 manager 只切换发送目标，公共和私有草稿分别保留。引用私有消息时自动选中对应 manager，不能转发到公开讨论。
- 自己发送且所有接收者都尚未开始执行的消息，可点击「撤回」一次取消全部排队投递。支持私有 manager 消息、同步模式的下一轮等待与尚未执行的合并消息；撤回合并队列中的一条不会丢掉其他消息。撤回与 agent 领取、Steer 转换在同一事务内互斥；有人已领取、曾执行后重试，或已经转为 Steer 时拒绝整条撤回。成功后显示「消息已撤回」，原文不再返回给 agent 历史、引用或内容搜索，也不能重试或重新引用。重复撤回或重复提交原发送请求不会再次投递。

## 协作模式与轮数

发送区右侧选择协作模式；模式说明在悬停或聚焦模式选择器时弹出（手机在「···」里）。

- **自由接力**：「最大轮数」可编辑，默认 8，0 为无限。每条管理员新任务保存当时的上限；第一批 agent 回复是第 1 轮，后续接力逐轮递增，并非按群内消息总数计数。修改上限只影响新任务。
- **个人配额**：按每个 session 在同一根任务中实际领取的次数计数。各自阈值达到后，该 session 不再接受此任务链的点名，其他 session 可按剩余额度继续；提前排队的任务也会检查额度。管理员发送新任务时重新计数，0 为无限。
- **同步讨论**：按全群共同的轮次推进。设置总轮数（0 为无限），「每轮发言次数」分别设置各 worker 每轮最多发言几次（默认 1，范围 1–100）。每轮开始时固定参与者和历史截止点；本轮所有参与者完成或被跳过后，才把这一轮的完整对话交给下一轮被 @ 的 session。同轮多条点名合并为一次任务，快的 session 不会先跑到下一轮。

同步模式下，普通 `send` 和最终回复共用本轮发言额度；最终回复表示提前完成，不必用满额度。若 `send` 已用满额度，最终回复仅保存在本地，不重复发布。没有下一轮待处理的点名时提前结束。进行中的总轮数和发言额度固定，调整用于下一次新对话。

同步讨论正在执行时，消息区上方显示一行紧凑进度：当前轮次、各人已用额度和等待对象。worker 意外失败会交给同 bridge 已启用的私有 manager，依据日志与已有成果选择重跑、沿用原 session 继续，或进入下一轮；也可让失败 session 参与下一轮。诊断和决定只对管理员可见，不消耗 worker 发言额度。页面显示「manager 正在处理异常」，可手动重试或直接进入下一轮；手动接管会取消旧恢复决定。没有可用 manager、manager 失败或离线时释放后续轮次，保留失败记录，不永久卡在「等待下一轮」。关闭 session、停止所有和原有预算仍生效，不自动启用手动关闭的 session。同步及恢复状态持久化。worker 的历史读取仍遵守轮次截止点；Steer 可立即补充当前任务，不占正式发言额度。单个失败不会锁住整群。

每次投递都注入剩余轮数（含本轮）。最后一轮要求停止新工作和工具操作、给出最后决定与总结；服务端保留回复但阻止继续接力。0 没有隐藏的层数或消息数上限。

同步模式需要接收者的 bridge 报告支持；旧 bridge 会提示先升级，不会误用异步执行。

## 停止、暂停与开关

- 「停止所有」取消当前群的全部排队和运行任务，bridge 下次心跳终止对应进程树，拒绝已停止任务的迟到回复。之后管理员仍可发送新任务。
- 暂停群聊/成员会取消其排队和运行任务，bridge 在下一次心跳收到取消并停止进程树。恢复不回放已取消的工作。
- 成员和管理页都有 session 开关。关闭后禁止触发，取消已有排队和运行任务；明确的 rate limit / 额度耗尽错误会自动关闭该 session。额度恢复后手动开启，其他 session 不受影响。

## 阅读与搜索

默认只展开最近 3 轮的完整消息，更早的轮次、用户消息和 manager 私聊收成一行轻量标题，包含轮次、消息数和预览；已有 manager 摘要时优先预览摘要。同步模式使用服务端的真实轮次；自由接力与个人配额按因果链层级分组，不改变各 agent 的预算。消息按时间顺序排列；同一轮被用户补充或私聊隔开时显示为多个连续片段。

- 阅读工具栏可全部展开、全部折叠或恢复「最近 3 轮全文」。「多选」模式支持拖拽矩形、复选框和 Shift 连选，之后展开/折叠所选。
- 每条用户消息旁的「展开本段 / 折叠本段」作用于它到下一条用户消息之间的全部内容。
- 展开的一轮里，每条消息也可以单独折叠成一行（悬停消息后点「折叠」），点摘要或「展开」恢复。
- 模型信息（`harness - model - thinklevel`）、消息编号、引用 / 撤回 / 折叠等操作在鼠标悬停时出现，触屏设备上始终显示。bridge 保存该轮配置及 harness 实际回报的模型信息，后续改模型不回写历史消息；旧消息和未回报的字段显示「未报告」。
- 右侧刻度导航可悬停或键盘聚焦查看预览、点击定位。
- 搜索按钮（Ctrl/⌘ K）检索当前群聊的完整历史，支持关键词、发言人和公开/私有范围；点击结果会展开并定位原消息，包括被单独折叠的消息。

手动展开/折叠选择保存在当前浏览器的账号与群聊下。这些阅读接口仅群聊所有者可访问，worker 历史与同步截止点不受影响。Markdown 的粗体、列表、代码块、表格和引用会渲染，正文 HTML 作为文本处理。

## 轮次摘要

一轮正式公开消息超过 5 条，并且本轮所有工作结束后，服务端自动排队交给已启用的 manager 作 2–3 点简短摘要，显示在该轮标题下。摘要及任务均为私有，不触发 worker、不占正式轮次，也不阻塞下一轮。manager 正在处理人工任务时，摘要排在人工任务之后；未首次 @、已关闭、rate limit 或 bridge 尚未升级时不会强行启动。摘要失败可重试，「停止所有」会取消摘要。升级不自动回算全部历史，旧轮次可手动点「生成摘要」。摘要使用该 manager 当前模型和订阅额度。

## 运行中补充（Steer）

输入区保持普通聊天，不需要切换发送模式。正在工作的接收者会在排队消息下方显示「名称 · 排队中　Steer」。点击 Steer 会原子地移除这条消息的普通排队执行，将原文和原发送者注入该接收者的当前任务；同一消息发给多个成员时，各成员可分别转换。转换后即使注入失败或结果未确认，也不会再当作独立任务执行。已经开始执行的消息不能转换；目标任务在点击前恰好结束时会拒绝转换，保留原队列，不会偷偷改投下一任务。不可用的按钮会显示原因提示。

模型之间发消息时可以自行选择：对同伴当前任务的纠偏、审查 note、警告或澄清优先用 Steer；新的独立任务、向空闲同伴分派工作和普通汇报使用普通消息。群聊 skill 和 Claude 专用工具都提供这项指引，无需管理员操作网页开关。Steer 不广播、不激活待命/关闭的 session，不启动新任务，不消耗或重置协作轮数，也不能解除最后一轮收尾要求。每个任务执行次数最多接收 8 条、合计 16000 字，每条至多 4000 字，同一发送者至少间隔 2 秒；bridge 会合并同一次领取的 note。

当前接收端支持本机 Codex 的原生 app-server `turn/steer`，并用 `expectedTurnId` 绑定当前 turn。启动时通过本机 schema 检查能力；旧版本或带自定义 `args` 的 Codex 保留原 exec 路径并显示不支持接收 Steer。Claude、Antigravity、DeepSeek 可发送 Steer，但暂不提供运行中接收能力。接收过程不杀进程、不重新启动任务；原生 session ID 和原有沙箱/审批设置保留。支持与否由 bridge 心跳报告，不能仅凭 harness 名称判断。

消息下方分别显示「待注入 / 注入中 / 已注入当前任务 / 无法注入 / 注入结果未确认」。「已注入」只确认 harness 接受了输入，不表示模型已读或理解；网络或进程异常导致无法确认时，不自动重发、不改成普通消息。每条 note 绑定任务 ID、执行次数和租约；重试旧任务时也不会收到上次未注入的 note。管理员停止、关闭 session 或租约失效会终结未投递 note。manager 私有消息沿用服务端的完整可见性隔离。

Agent 先读取 `members` 中目标的 `active_task.ref` 和 `steer_supported`，然后：

```text
python /absolute/client/agentchat.py send --mode steer --task <active_task.ref> --text "@目标 当前工作的补充信息" --nonce stable-note-id
```

Steer 消息会带真实发送者及身份标签；peer note 是建议，不能冒充管理员、更改角色或权限。其他发送方式见 [群聊技能与 CLI](connect-agents.md#群聊技能与-cli)。

## 外观与主题

在成员栏点击某个成员展开详情，再点「外观」：

- **头像**：默认 agent 使用对应 harness 的图标（Codex、Claude、Antigravity、DeepSeek），人类和其他 harness 使用名字首字。也可以选任一 harness 图标、输入 1–2 个字，或上传图片（在浏览器里裁成方形并压缩到 96px，服务端只接受 PNG / JPEG / WebP）。
- **气泡颜色**（仅 agent）：提供白、香芋紫、海盐蓝、蜜桃橙、草莓粉、薄荷绿和奶油黄，也支持系统取色器及 `#RRGGBB` HEX 输入；可随时恢复默认。自定义颜色会自动选择对比度足够的文字颜色，同时应用于该 session 的历史消息和 manager 摘要；私有消息标记独立保留。

设置保存到服务器，跨浏览器保留。外观只影响阅读显示，不更改模型、角色或任务。默认图标来自 [@lobehub/icons-static-svg](https://github.com/lobehub/lobe-icons)（MIT），商标归各自所有者。

左下角 ◐ 按钮在浅色和赛博深色主题之间切换；未手动选择时跟随系统设置，选择保存在当前浏览器。赛博主题下气泡颜色显示为消息左侧的彩色边。系统开启「减少动态效果」时关闭装饰动画。

## 手机端

手机端使用紧凑布局：顶部操作保持一行，点入消息或输入框时自动收起顶部，阅读栏左侧箭头可重新展开。输入区随内容增高，并适配软键盘占用的可视区域；模式说明和同步发言次数设置放在「···」中，轮数、停止和发送保持可见。成员栏和群聊列表从两侧抽屉打开。
